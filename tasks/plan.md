# 双包差异对比实现方案

状态：用户于 2026-10-21 授权实施，双包对比开发中；与追踪流性能修复一起交付 5.1.2。

## 1. 首版目标与范围

在同一份抓包中选择两个已经捕获的包，直接比较协议字段和原始字节，回答三个问题：哪些字段的值变了、哪些字段只存在于其中一包、变化对应哪些字节。

首版包含：

- 同一文件的两个包；一次选两包，或先设基准包再选另一包。
- 对齐的字段树、并排 Hex/ASCII、差异统计、上一个/下一个差异。
- 只看差异、交换左右、可见的忽略规则、复制对比结果。
- 中文界面；协议、字段 abbreviation 和过滤语法保留英文。

后续扩展：跨文件对比、整条流对比、批量对比、文件化报告。首版不修改数据包、不发送或回放请求，也不改变主列表的过滤器和动态解码列绑定。

## 2. 入口与操作

### 同时选择两包

包列表选中恰好两个不同的包时，右键菜单和 Analyze 菜单启用“比较选中的两个包…”。按照文件中的帧号确定初始左右顺序，左侧为较早的包。选中数量不符合条件时给出明确的禁用原因。

### 基准包方式

单包右键“设为对比基准包”，随后在另一包右键“与基准包比较…”。基准标识与原有 Mark 状态独立，不借用或改写 Mark。基准状态显示帧号，提供“清除基准包”。

对比窗口打开后固定这两包的快照。主窗口继续选包或改过滤器时，对比内容保持稳定。关闭、重载或更换源文件后，清除主窗口的基准；已经打开的快照仍可阅读，但禁用跳回失效文件的操作，并标明来源已关闭。

## 3. 窗口布局

```text
比较数据包     左：#128 / TCP / 74 bytes     右：#364 / TCP / 78 bytes
[交换左右] [只看差异] [计算字段] [忽略规则：3] [上一个] [下一个]

字段树                         左包值             右包值             状态
  Ethernet
  IPv4
    ip.len                     60                 64                 修改
  TCP
    tcp.options...             —                  ...                仅右侧

左侧 Hex / ASCII                                 右侧 Hex / ASCII
选中字段对应范围 + 全部差异范围                    对应字段范围 + 差异范围

修改 4 项 · 仅左侧 1 项 · 仅右侧 2 项 · 忽略 3 项
```

字段部分使用一棵对齐树及“左包值 / 右包值 / 状态”列，展开、折叠和滚动天然同步。字节部分是两个独立视图，按照字段映射联动；不把两侧相同偏移错误地当作同一字段。

差异同时用文字、图标和主题颜色表达，保证深浅主题及色觉差异用户都能识别。切换“只看差异”时保留包含差异的祖先节点。多字节字段和 bitmask 字段均显示明确范围；没有原始字节来源的计算字段不伪造字节高亮。

## 4. 字段比较规则

### 比较值，不比较界面字符串

解析和格式化复用 libwireshark。相同类型的实际字段值使用现有 `fvalue_equal` 等类型能力比较；显示值沿用 Wireshark 的格式化结果。名称解析、中文翻译、十六进制/十进制显示变化不应制造差异。

`FT_PROTOCOL` 和 `FT_NONE` 主要承担分组作用；父节点状态由子节点汇总。纯文本诊断项单独标识，不承诺它与有类型的字段具备相同的语义比较能力。

### 字段匹配

- 用协议层级、父节点路径、字段 abbreviation 及出现位置形成身份候选，同类型优先配对；剩余同身份、异类型的字段标记为类型变化。不能只用名称，也不能把整棵树摊平后只按 hf ID 配对。
- IPv4-in-IPv4、重复 VLAN、多个 TLS record、重复 HTTP header 等保留各自层级。
- 重复兄弟字段先以不变项为锚点进行有序对齐，再处理剩余项；对齐预算受限。
- 缺失、增加和类型变化分别表示。没有足够证据判定重复项对应关系时显示“匹配不确定”，不把启发式结果包装成协议级身份识别。
- 字段匹配不依赖原始字节偏移，因为插入一个 option 可能改变后续所有字段的偏移。

### 默认忽略与可解释性

默认使用“协议内容”视图，将帧号、采集时间、用户标记等采集/操作元数据排除出主要统计；提供“全部字段”视图。具体忽略项始终可查看，忽略数量始终可见。

真实的长度、地址、端口、TCP flags、线上的序列号和校验和值默认保留。忽略 IP ID、TCP seq/ack、校验和等动态字段是用户主动选择的预设，不做静默忽略。计算字段默认单独关闭，开启时明确提示其值可能依赖会话上下文；例如相对 TCP 序列号与线上原始序列号要区分。

隐藏一个字段在结果树中的行，不会自动抹掉其原始字节差异。只有覆盖范围明确、两侧映射可靠的忽略项才可屏蔽对应字节；重叠/位域规则需明确，首版优先保持字节结果完整。

## 5. 字节比较

首版默认采用“按偏移比较”：线性比较原始包的各个字节，合并连续差异范围；长度多出的尾部显示“仅左侧/仅右侧”。它是准确的偏移差异，不把中间插入引发的后续错位误报成已经识别出的真实插入操作。

协议字段树提供语义对齐，可直接定位因 option/header 长度变化而移动的字段。字段选择使用各自数据源和范围高亮，避免盲目同步偏移。

“按内容对齐”作为独立的第二阶段：裁剪共同前后缀后做有预算的序列差异算法；超出预算时明确回退到按偏移比较。避免对任意大字节串直接运行无上限的 O(N×M) 算法。

原始 Frame 是默认数据源。解密、解压、重组数据通过独立数据源选择器处理，明确标出数据源名称和长度；不同类型的数据源不自动交叉配对。抓包截断显示为“未捕获”，不当作已证明不存在的字节。

## 6. 源码与生命周期

当前可复用的路径：

- `ui/qt/packet_dialog.cpp`：`cf_read_record`、`epan_dissect_init`、`epan_dissect_run` 的单包读取和解析方式。
- `ui/qt/utils/field_information.*`、`utils/proto_node.*`：字段信息和协议树访问。
- `ui/qt/widgets/hex_data_source_view.*`：Hex/ASCII 绘制、选区及 `setAnnotations` 范围着色能力。
- `epan/ftypes/ftypes.h`：有类型字段值的比较能力。

建议新增的职责：

| 文件 | 职责 |
| --- | --- |
| `ui/qt/packet_comparison_dialog.{h,cpp,ui}` | 对比窗口、操作与主窗口衔接 |
| `ui/qt/utils/packet_comparison.{h,cpp}` | 字段匹配、差异状态、字节范围计算 |
| `ui/qt/models/packet_comparison_model.{h,cpp}` | 展示一棵对齐树，过滤相同节点 |
| `test/qt/packet_comparison_test.cpp` | 纯比较逻辑回归 |
| `test/qt/packet_comparison_integration.*` | 真实抓包、入口与生命周期验证 |

主线程在现有 capture/epan 上串行读取和解析这两包，保留已有会话上下文，不重扫全文件。遇到文件正被读取/重解析时延后启动或给出忙碌状态，禁止嵌套解析。不要为“异步”把当前共享 `capture_file` 或 epan 会话移入工作线程。

两包分别使用独立的 `epan_dissect_t`，都保活到有类型值比较结束；如果需要单独保存字段值，则通过现有 `fvalue_dup` 等接口建立自有副本，不能复用同一个解析上下文后访问第一包的旧值。在临时解析上下文有效期间完成有类型值比较，并把 UI 所需的字段信息、显示值、数据源字节、范围等复制为自有结果。窗口和后台纯字节 diff 不保存临时 `FieldInformation*`、`proto_node*` 或 `tvbuff_t*`。清理解析上下文后，快照不依赖当前主窗口选中包。

优先新增局部模块，复用 Hex 视图，避免改写 ProtoTree 的通用行为。若现有高亮 API 足够则直接使用；只有实际不足时才增加小范围通用接口。纯 diff 工作可以交给现有 Qt Concurrent，不新增第三方依赖。

## 7. 性能与资源边界

- 只读取和解析两包；过滤器、忽略规则和视图开关变化尽量在缓存结果上重算。
- 按偏移字节差异为 O(N)，树的常规匹配接近线性；重复项对齐设计算预算。
- 合并连续高亮范围，绘制只处理可见行，避免为每个字节创建 QWidget 或树节点。
- 大数据源延迟显示，后台计算可取消；取消后不得覆盖新的对比任务。
- 不对活的 epan 指针调用随意的 `processEvents` 来制造响应性；解析与纯计算的边界必须明确。
- 首轮以普通 MTU、64 KiB、大量重复字段和多 MiB 重组源测量时间/峰值内存，再确定预算，不把未经测量的毫秒值写成已达到的性能承诺。

## 8. 实施步骤与验收

1. **贯通最小比较**：真实两包读取、固定快照、左右值与基础差异。用相同包和单字段变化证明正确性。
2. **接入入口与生命周期**：两包选择、基准包、重载/关闭/过滤后行为。检查主列表和动态解码列没有副作用。
3. **完善结构匹配**：重复字段、封装层、缺失字段、计算字段、忽略项。加入确定性和不确定性用例。
4. **联动字节视图**：偏移差异、尾部范围、bitmask、截断和数据源隔离。
5. **交互与发布验证**：搜索/差异导航/复制、中文、深浅主题、高 DPI、Windows/macOS/Linux 构建及运行验证。
6. **后续增量**：有预算的按内容对齐，再考虑跨文件；每项独立验证，避免首版范围失控。

关键验收矩阵：

| 场景 | 必须满足 |
| --- | --- |
| 相同内容、不同帧号/时间 | 协议内容视图无虚假差异；全部字段可见真实元数据差异 |
| 数值相同、显示格式不同 | 不因进制、名称解析或语言变化而不同 |
| 单值/重复值/类型变化/字段缺失 | 状态和计数正确，层级稳定 |
| IP options、VLAN、封装层增减 | 不因整体偏移变化错误配对所有字段 |
| 不同 link type/完全不同协议 | 各自显示独有结构，不强行配对 |
| 位域、重叠字段、生成字段 | 对应高亮正确；无字节来源时明确提示 |
| pcap/pcapng、截断包、畸形包 | 显示解析状态，读取失败不崩溃、不留下半初始化窗口 |
| 抓包继续、改过滤器、重载/关文件 | 快照稳定，无悬空指针，无跳回错误文件 |
| 忽略动态字段 | 忽略项可见可撤销；不掩盖无关差异 |
| 大包及大量重复项 | 算法有界，可取消，不长时间阻塞主界面 |

## 9. 本轮独立处理：追踪流性能

已核对官方 `v4.6.9` 源码：它通过主列表 display-filter 的扫描同时触发 Follow tap。当前分支则先 `retapPackets()`，在 `endRetapPackets()` 绘制完整流，然后再发 `updateFilter` 触发第二次扫描。

修复方向：注册 Follow tap 后直接请求应用流过滤器，监听该扫描生命周期，在结束时移除 tap 并显示流内容。保留主窗口已有的队列机制，处理同过滤器重开、流切换、关闭/取消及其他统计窗口共存，避免嵌套扫描和双重收集。

验收：一次正常追踪只进行一次主列表扫描，不再额外 retap；主列表与流内容来自同一遍数据处理。TCP/UDP 开启、切换、相同过滤器重开、Close 保持当前过滤器、Back 恢复打开前过滤器必须通过真实 GUI 集成测试，并记录有代表性负载下的修复前后耗时。

## 实施记录（2026-10-22）

- 入口与快照窗口已实现；用户于 2026-10-21 明确授权上代码。
- 窗口直接使用局部 `QTreeWidget`，没有另建通用 model 或 `.ui` 文件；字段匹配与字节算法保留独立可测模块。
- 重复容器用子字段类型和值寻找锚点，单组对齐上限 65,536 个单元，全局语义匹配预算 131,072 次；不足时标记匹配不确定，最终字段值仍精确比较。
- 每包数据源总量限制 64 MiB，协议树限制 50,000 字段 / 256 层，超出明确报错。Hex 只为可见区域创建高亮范围，全局统计使用线性扫描，不为密集差异保存全量注释对象。
- 原始及派生数据源按名称和出现顺序分别选择；默认 Frame。计算字段默认排除，也显式排除上下文相关 `tcp.seq` / `tcp.ack`，保留 `tcp.seq_raw` / `tcp.ack_raw`。
- 追踪流真实 GUI 与 100014 包固定负载已通过：TCP/UDP 从一次 Retap 加一次 Rescan 改为仅一次 Rescan，八项操作单次对照耗时下降约 46–48%。这不是对所有抓包的性能承诺。
- 原始 Frame 字节直接复制 record buffer，使用捕获长度及线上报告长度；派生 TVB 的长度变化不会丢掉 Frame padding 或截断信息。
- 原生 macOS Cocoa 暗色验证发现空白区交替底色与差异文字对比不足；只在新对比树关闭交替底色，差异状态使用默认文字颜色加粗，保留原生选中/焦点行为及 Hex 范围着色。
